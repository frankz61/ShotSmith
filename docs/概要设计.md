# ShotSmith —— 概要设计文档

> 上游依据：[需求文档](需求文档.md) · [技术架构选型](技术架构选型.md)
> 范围：MVP（单商品：抠图 + 白底主图 + 场景图 + 还原度校验 + 打包下载）
> 状态：初稿，待评审

---

## 1. 系统总览

把需求里的"一张图 → 一套素材"落成一条**可观测、可重试、模型可插拔**的流水线。分五层：

```
┌──────────────────────────────────────────────────────────┐
│  ① 接入层  FastAPI（REST）+ Gradio（MVP 前端）              │
│     上传/URL、提交任务、查进度、挑选、下载                    │
├──────────────────────────────────────────────────────────┤
│  ② 编排层  Celery Worker：把任务拆成流水线阶段，逐段执行       │
│     状态机 / 进度上报 / 失败重试                             │
├──────────────────────────────────────────────────────────┤
│  ③ 流水线  ingest→preprocess→matting→generate→post→QC→package│
│     每个阶段输入输出有明确契约                                │
├──────────────────────────────────────────────────────────┤
│  ④ 适配层  Provider 抽象：Matting / ImageGen / Fidelity     │
│     rembg、商用图像 API…可替换，业务不感知                    │
├──────────────────────────────────────────────────────────┤
│  ⑤ 存储层  PostgreSQL（任务/素材元数据）+ FS（图片）+ Redis    │
└──────────────────────────────────────────────────────────┘
```

## 2. 核心流程（单商品生成时序）

```
用户        FastAPI          DB         Celery/流水线        Provider
 │  POST /tasks  │            │              │                 │
 │─(图+描述+选项)→│  建任务(PENDING)          │                 │
 │            │──写入──────→│              │                 │
 │            │──入队────────────────────→│                 │
 │←─ 202 {task_id} ─┤        │              │                 │
 │                            │   PROCESSING  │                 │
 │                            │  ① ingest 校验/取图             │
 │                            │  ② preprocess 规整              │
 │                            │  ③ matting 抠图 ───────────────→│ rembg
 │                            │  ④ generate 白底+场景(N张) ─────→│ 图像API
 │                            │  ⑤ postprocess 尺寸/补阴影      │
 │                            │  ⑥ QC 还原度校验 ──────────────→│ DINOv2
 │                            │  ⑦ package 写素材+元数据         │
 │                            │←─ SUCCESS / PARTIAL ─┤          │
 │  GET /tasks/{id}（轮询）    │              │                 │
 │←─ status + 进度 + 素材列表 ─┤              │                 │
 │  GET /tasks/{id}/package   │              │                 │
 │←──────── zip 素材包 ───────┤              │                 │
```

任意阶段失败 → 该任务标 `FAILED` 并记录失败阶段与原因，支持整任务或按阶段重试。

---

## 3. 流水线阶段契约

每个 stage 是一个纯函数式步骤：`(ctx, input) -> output`，输出落盘并记录到 DB，便于断点重试与排查。

| # | 阶段 | 输入 | 输出 | 关键点 |
|---|---|---|---|---|
| 1 | **ingest** | 上传文件 / 图片 URL | 本地原图 | 格式(jpg/png/webp)、最小分辨率、能否识别主体；URL 抓取超时/失败处理 |
| 2 | **preprocess** | 原图 | 规整图 | EXIF 旋转校正、过大图缩放、色彩空间统一 |
| 3 | **matting** | 规整图 | 透明底 PNG + mask | 调 `MattingProvider`；边缘质量；难例打标 |
| 4 | **generate** | 透明底图 + prompt + 选项 | 白底主图 + 场景图 ×N（候选） | 调 `ImageGenProvider`；**商品保持**；按品类默认 prompt 或用户描述 |
| 5 | **postprocess** | 候选图 | 适配尺寸的成品 | 主图补阴影、按 1:1/3:4/4:5 裁切/补边、白底纯净度检查 |
| 6 | **QC** | 成品 + 原图 | 每张打 `fidelity_score` + 状态 | `FidelityProvider` 算相似度；< τ → `NEEDS_REVIEW` |
| 7 | **package** | 通过的成品 | 素材包目录 + `metadata.json` | 按类型归类，写生成参数 |

> 阶段间用 `task_id` 下的工作目录传递文件，DB 记录每张产物的路径与元数据。

## 4. 模型适配层（可替换的关键）

业务只依赖**抽象接口**，具体实现按配置注册，换厂商=换实现，不动流水线。

```python
# providers/base.py（接口示意）

class MattingProvider(Protocol):
    def cutout(self, image_path: str) -> CutoutResult: ...
    # CutoutResult: rgba_path, mask_path, edge_quality

class ImageGenProvider(Protocol):
    def generate(
        self, product_cutout: str, prompt: str, params: GenParams
    ) -> list[GeneratedImage]: ...
    # 约束：必须保持商品主体；返回 N 张候选

class FidelityProvider(Protocol):
    def score(self, original: str, generated: str) -> float: ...
    # 返回 0~1，越高越还原

# providers/registry.py：按 settings 选择实现
PROVIDERS = {
  "matting":  {"rembg": RembgProvider, "cloud": CloudMattingProvider},
  "imagegen": {"vendor_a": VendorAProvider, "self_sd": SelfHostedSDProvider},
  "fidelity": {"dinov2": DinoV2Provider},
}
```

MVP 注册：`matting=rembg`、`imagegen=vendor_a`、`fidelity=dinov2`。
二期自建只需新增 `self_sd` 实现并改配置，业务零改动。

## 5. 数据模型

**task（生成任务）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid | 主键 |
| status | enum | PENDING/PROCESSING/SUCCESS/PARTIAL/FAILED |
| current_stage | str | 当前/失败所在阶段 |
| source_type | enum | upload / url |
| source_ref | text | 原图路径或 URL |
| description | text | 可选文字描述 |
| options | jsonb | image_types、sizes、style、候选数 N 等 |
| error | text | 失败原因 |
| created_at / updated_at | ts | |

**asset（生成素材）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid | 主键 |
| task_id | uuid | 外键 |
| type | enum | white_bg / scene |
| size | str | 1:1 / 3:4 / 4:5 |
| path | text | 文件路径 |
| fidelity_score | float | 还原度 0~1 |
| qc_status | enum | PASSED / NEEDS_REVIEW / REJECTED |
| selected | bool | 用户是否选用 |
| gen_params | jsonb | provider、prompt、seed 等 |

**任务状态机：**

```
PENDING ──→ PROCESSING ──→ SUCCESS        （全部产物 QC 通过）
                  │      ──→ PARTIAL        （部分通过/部分待复核）
                  └──────→ FAILED          （阶段异常）
   FAILED / PARTIAL ──(重试)──→ PROCESSING
```

## 6. API 设计（REST，`/api/v1`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/tasks` | 创建任务：multipart 上传或 `{url, description, options}`，返回 `task_id` |
| GET | `/tasks/{id}` | 任务状态、当前阶段、进度、素材列表摘要 |
| GET | `/tasks/{id}/assets` | 素材明细（含 fidelity_score、qc_status） |
| POST | `/tasks/{id}/regenerate` | 整任务或指定 `type/asset_id` 重新生成 |
| POST | `/assets/{id}/select` | 标记选用（可选） |
| GET | `/tasks/{id}/package` | 下载 zip 素材包 |

请求/响应全部用 Pydantic 模型校验；进度 MVP 用轮询，二期可加 WebSocket/SSE。

## 8. 还原度校验设计（落实第一约束）

```
原图 ──┐                        ┌─→ score ≥ τ → PASSED
       ├─ matting 取商品区 ─→ DINOv2 嵌入 ─ 余弦相似 ─┤
生成图 ┘  （或复用生成时的mask）              └─→ score < τ → NEEDS_REVIEW
```

- 比对的是**商品区域**而非整图，避免背景差异干扰。
- MVP **不硬卡**：低分只打 `NEEDS_REVIEW` 让用户复核，阈值 τ 由 PoC（选型文档 §7-3）标定。
- 二期可对 `NEEDS_REVIEW` 自动触发重生成。

## 10. 错误处理与重试

- **阶段级隔离**：每阶段 try/except，异常记 `task.error` + `current_stage`，不污染其他任务。
- **重试**：Celery 自动重试网络类错误（指数退避）；业务类失败（如抠不出主体）直接标失败并给明确提示。
- **批量（二期）**：单 SKU 失败不阻塞整批；批任务聚合子任务状态。
- **幂等**：重试以 `task_id` 工作目录为基准，覆盖式重算，避免脏数据。

|---|---|---|
| 图片输入（上传/URL） | ✅ | ingest |

| 可选文字描述 | ✅ | generate（prompt） |
| 白底主图 | ✅ | generate + postprocess |
| 场景图 | ✅ | generate |
| 多尺寸导出 | ✅ | postprocess |
| 预览 / 重生成 | ✅ | API + regenerate |
| 打包下载 | ✅ | package |
| 商品还原度 | ✅（校验+人工复核） | QC |
